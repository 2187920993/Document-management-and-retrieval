# 发布检查清单

文档编号：OPS-021  
版本：1.4  
维护团队：平台运维组  
更新日期：2026-09-16  
用途：生产版本发布的通用操作规范

## 1. 发布前准备

确定发布负责人、观察人员和变更窗口。记录本次提交 SHA、镜像标签与镜像摘要，确认前端、API 和索引任务服务来自同一份发布清单。使用固定版本标签，不以 latest 作为唯一回退依据。

检查配置差异：数据库连接、文件存储路径、任务队列、模型服务地址及超时。配置核对只记录字段名和是否变化，不在工单中粘贴密码。提前确认磁盘剩余空间足够保存新镜像、已有文件和备份。

## 2. 数据与回退准备

涉及数据库迁移时，在发布前生成备份并验证备份可读取。说明迁移是否向前兼容：新增表或可空字段与删除旧字段的风险不同。不能因为有备份，就默认恢复时没有数据损失。

保留上一版本镜像、部署配置和启动命令。回退计划必须说明哪些服务需要一同回退、数据库结构是否兼容以及新产生的数据如何处理。回退应用镜像并不会自动撤销数据库迁移，也不会恢复已删除文件。

## 3. 启动后的业务检查

- 检查 API、数据库和后台索引服务，不以“容器处于 running”作为全部通过。
- 上传一份专用验证文档，核对文件详情，再下载并比对内容。
- 等待该文档显示可检索后，用文件名和正文各搜索一次。
- 将验证文档归档，确认默认列表与默认搜索不再出现；恢复后再次确认可用。
- 检查错误日志、请求失败率和待处理任务是否持续积压。

测试材料需要明确标为验证用途，不使用真实用户材料做删除或覆盖测试。验证结束后按记录清理测试数据。

## 4. 观察与停止条件

本项目发布后至少观察十分钟。若新版本导致持续的服务端错误、上传文件无法下载，或索引任务完全停止消费，应暂停继续发布。排查配置问题时也要记录影响范围，不能反复重启来掩盖故障。

在数据结构兼容且恢复方案已确认的前提下，可切回上一版本应用。恢复后再次执行上传、下载和检索检查。若无法直接回退，则停止进一步变更，记录故障并执行已审查的修复方案。

## 5. 发布记录模板

记录发布时间、实际发布版本、镜像摘要、迁移结果、业务检查结果和观察结论。失败项填写实际现象，不能勾选为通过。通用清单只说明应该做什么，某一天做了什么应写入对应项目的发布执行记录。
